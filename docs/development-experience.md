# 阶段反思与开发经验

更新：2026-10-22。当前能力与证据见 [阶段性验收](milestone-acceptance.md)，下一批只按 [TODO](../TODO.md) 执行。本文记录可复用的判断，不重复堆叠开发流水账。

## 本阶段取得了什么

项目从“独立角色能执行短命令”推进到“真实模型选目的地、使用原生工具、主动返程”的单人前台闭环。阶段任务8次请求正常结束，确认挖掉3块，home到达误差约3.24像素；不等于长期自主生存、完整战斗或正式发布已完成。

最有价值的进展是把职责分清：模型选目标和处理较慢的策略，本地控制负责连续输入、减速、边界和结果判定。现有标准库循环已能完成这一阶段，不需要先迁移框架；以后复杂度确实增长时仍可评估LangChain／LangGraph。

## 从真实失败中得到的判断

| 现象 | 证据与原因 | 今后的做法 |
| --- | --- | --- |
| 同批移动后攻击，角色没先走到位 | 命令按顺序下发，但新动作覆盖旧输入 | 明确每个工具何时返回；先后动作由宿主等待，边走边跳则保留组合输入 |
| 反复挥镐却不变方块 | 原失败坐标树干支撑受保护，CanKillTile=false，原生伤害置0 | 候选先排除明确不允许的动作；范围、世界允许、工具强度和实际成功分别表达 |
| 模型把jumpClearance=false解释为没空间 | 无障碍时该字段也为false | 字段必须说明适用条件，独立提供headClear；先改善观察，不把误读全归为模型能力不足 |
| 提示词要求不超过25格，仍走过头 | 秒数不是位置，且有加速、惯性、地形与击退 | 模型选目的地，本地按实际位置刹停并执行边界；不能只加更强的提示词 |
| 能看到受伤，却不知道往哪里打／退 | 历史hurt没有当前敌怪位置 | 给局部敌怪位置／距离；观察时效和近敌快速反应仍需分开解决 |
| 显示到达后，最终位置又偏离 | 总结期间仍被怪物击退 | 区分动作完成时刻、最新状态与持续守位；不把到达一次说成持续保持 |
| 切回聊天后超时 | 本机失焦时世界／入口停止响应 | 原生暂停与控制缺陷分别定位；超时结果未知，恢复先看状态，不盲目重放 |

树下保护先用同坐标4次无变化建立可失败复现，再对照原生规则与现场树干信息，最后验证立即拒绝。敌怪击退同时发生，但不能拿它解释此前所有空挖。这种对照比只凭画面猜原因有效。

## 更大胆地做真实体验，同时给检查设停止条件

必要机制拿到一个代表性结果后，尽早让真实模型使用它。用户需要的是能玩的小场景，不是先补齐整套武器、百科、测试地图或框架。允许体验失败，依据实际卡点选下一批。

每批先给一个可体验交付与少量必要检查；通过就停止扩大范围。旧机制只有被改动或出现具体风险时才补回归。同一机制选代表，不逐把验收；说明文字修改不重复启动游戏、打API或重刷已通过场景。

临时验收脚本可能失败：本地10项检查通过后，末尾额外stop曾失焦超时；记录保留该错误，后续实际stop补足当前收尾，不把整轮从头再跑当默认方案。测试脚本问题不能忽略，也不能因此把小功能扩成新基础设施。

## 结果必须对应具体事实

- 命中看本次攻击者、武器、目标和原生item-hit，不能只看目标掉血或挥剑动画。
- 挖掘区分草地变泥土、方块移除、掉落存在和物品入包；当前只通过了前两步。
- 移动看本次目标sequence、实际位置、低速／落地及到达状态；死亡／重生不是返程，部分进展不是到位。
- 命令接受、动作结束、目标完成、模型正常结束分别记录。4轮预算用尽不抹掉已确认的物理挖掘，也不能写成模型正常完成。
- 本地活动范围约束主动输入，不是物理围墙；击退、重生和环境仍可造成出界。外界作用不应靠传送或改速度掩盖。

模型总结只是报告，宿主保留实际游戏状态和事件。没有证据时明确未确认；不因此建立通用全游戏验收器。

## 原生机制、工具与运行环境

继续让Player原生循环处理移动、碰撞、使用冷却、伤害和重生；只补额外玩家槽位被跳过的必要分支。不重复调用Player.Update，不切换Main.myPlayer，不直接删除方块或扣血制造成功。共享tileTarget只在原生调用内临时替换，并用finally恢复。

优先用现有JSON入口、结构化状态和已有本机库。通用键盘注入故障不应占据角色功能批次；辅助方案连续受阻时换路或报告限制，不继续造工具。

外部Agent／提示词／文档改动复用运行中的游戏。C#重建遇到tmod占用时，原生禁用／重载释放包的较短流程仍未实测走通；当前确认可用的是关闭旧实例后构建、重新加载。不能把计划中的热重载写成已验证能力，也不为尝试菜单或热更新单独反复重启。

专用测试角色和世界可作为夹具；使用改变规则的辅助功能时记录开关。测试发木剑／铜镐不等于普通初始装备已接入，测试末尾移除对象也不等于关闭默认自动重生。

## 阶段性不足与投入顺序

现在最明显的体验阻碍是失焦导致任务中断，其次是API等待期间缺乏及时自卫，以及资源不能确认入包。下一批先处理失焦任务连续性，之后按真实问题推进近敌反应、拾取与持续行为；不同时铺开全部模块。

最新完整任务累计153,201 tokens，明显高于最初39,505；包含缓存和重复历史，不是单请求上下文或金额。用户先前接受首轮开销，不代表已经确认数小时或新增观察后的预算。后续按 [上下文分析](agent-context-cost.md) 刷新数据，优先随功能减少重复状态、采用有界历史；不让压缩或大型RAG／记忆库成为功能前置。
