# Agent 长时间运行的上下文开销分析

日期：2026-10-21。基于已有首轮报告离线分析，本次没有追加 API 请求、游戏动作或性能测试，也没有实施上下文压缩。

## 当前判断

用户明确：目前一轮约 4 万 tokens 可以接受，不应为了省这部分开销阻塞功能开发。优化作为后续待办；在 AI 能听取游戏内指令、持续跟随、基础战斗及初步协作探索之后，准备数小时运行时再按实际数据实施。当前系统只是有限轮次的外部 Agent 原型，不是可持续陪玩系统。

## 这一轮数据说明什么

来源：`.local/test-results/agent-20261021-224015-302248.json` 的逐次 usage，7 次模型请求。

| 项目 | tokens |
| --- | ---: |
| 输入合计 prompt_tokens | 38,734 |
| 输出合计 completion_tokens | 771 |
| 总计 total_tokens | 39,505 |
| API 标记的缓存命中输入 | 29,952 |
| API 标记的缓存未命中输入 | 8,782 |

输入占总量约 98.0%，输入中的缓存命中约 77.3%。缓存输入仍计入 total_tokens，所以不能把 39,505 当成全部新输入，也不能直接用一个统一单价估算费用。本笔记不估算金额；实际金额需结合当时供应商对各类 tokens 的计费规则。

每次输入依次为 2195、3331、4445、5516、6661、7764、8822。`agent/run.py` 将旧 assistant 消息和完整工具结果持续追加到 messages，每次带上全部历史；每个工具结果又包含最新状态和最近 12 条事件，同一事件可能反复出现在多轮状态中。

因此已证实的是输入随轮次增长、缓存已有明显命中；目前没有精确按字段分词，不能给出每个状态字段占比或承诺某个优化能节省多少。7 次短任务也不能外推为三到六小时的实际用量。

## 优先怎样减少长期累积

| 顺序 | 做法 | 对持续游玩的意义 |
| --- | --- | --- |
| 1，随功能开发完成 | 本地持续动作，例如跟随目标、向目的地移动、攻击指定敌人；模型负责选择目标和策略，控制层负责连续执行 | 避免每走一小段就重新请求模型；同时解决现在行动衔接不完整的问题 |
| 2，随任务循环完成 | 关键事件触发决策：用户新命令、敌情变化、低血、受阻或动作完成；期间本地继续执行或待机 | 降低无意义的查询和相同决策次数；不是每帧或固定高频调用 API |
| 3，长时间运行前 | 为历史设置上限：固定能力说明＋当前目标＋最新状态＋少量近期完整工具轮次＋结构化进度 | 防止同一 messages 列表无限增长；保留调用与工具结果配对，不能随意截断成无效对话 |
| 4，长时间运行前 | 事件去重／增量发送，按 tick 和实体保留新增事件；定期或必要时补完整当前状态 | 不反复发送同一批受伤、命中事件；同时保留能够证明任务进度的事实，避免模型遗忘后误报 |
| 5，有数据再做 | 保持系统提示词和工具定义前缀稳定，动态状态放后面；沿用供应商已有缓存 | 当前已受益，不需要为此单独建设缓存服务；缓存有利于计费／重复计算，但不能替代上下文长度管理 |

完整原始报告可以保存在本地，模型只接收当前决策需要的部分。结构化进度优先由宿主从游戏事件整理，例如当前用户目标、跟随对象、上一个动作结果、已确认命中、失败原因；不为每轮总结再调用一次模型。开放探索中确实需要自然语言记忆时，再考虑低频检查点摘要，不能先建设大型记忆／RAG 系统。

当前输入按历史长度持续增长；若每轮新增量近似固定且全部重发，累计输入呈近似二次增长。有界历史能限制每次请求的历史部分，使累计量更接近随请求数线性增加。这是代码结构分析，不是本项目的长时实测节省比例。调用频率、观察大小、任务行为和缓存命中都会改变实际结果，不能仅按这轮平均用量乘游玩时长。

## 为什么现在先不做

首轮的主要问题是移动后立刻攻击取消了尚未完成的移动，以及模型误判命中。先让动作可靠执行、结果能反馈，往往也会减少无效重试。现在提前压缩提示词或清空历史，可能损失关键事实，让这两类问题更难处理。

当前 `-Goal` 能把命令行自然语言任务交给模型，但缺少游戏内便捷指令入口、稳定持续任务循环、可靠跟随与下矿探索能力。先完成这些，再观察实际的调用频率和历史增长，不以节省 tokens 代替产品能力验收。

## 后续实施时的最小观察

继续使用已有 API usage 和任务报告，按任务／时间段汇总请求次数、输入／输出、缓存命中／未命中，以及任务完成和卡住情况即可。发现重复轮询、同一事件反复发送或单次输入持续增长，再处理相应问题。一次只改一个已发现的大头，检查任务可靠性是否保留；不增加昂贵的独立压测或复杂监控平台。

目前为分析与待办，没有宣称压缩已经实现或长时间游玩已经可用。
