# API Agent 接入准备

状态：2026-10-21，已接通真实 DeepSeek API，并执行一次模型驱动游戏测试。木剑命中已确认，铁阔剑目标未完成；不能将 API 接通等同于自主战斗任务全部通过。

## 发给模型的内容

每次新任务由三部分开始，不重复发送整份 README、历史调试记录或游戏百科：

1. 系统提示词：`agent/prompts/system.md`。简明说明角色身份、已实现的能力、已知限制、自动重生和结果判断方式。
2. 本轮目标：用户命令或 `agent/prompts/weapon-test.md`。目标与长期能力说明分开，方便之后替换成跟随、战斗等任务。
3. 初始观察与工具定义：由宿主读取游戏当前状态；工具定义说明动作、参数及结果，不能只让模型猜聊天命令。

当前有用观察为游戏 tick、是否暂停、AI 的位置／朝向／生命／武器／动作状态、可观察目标和最近少量事件。输入诊断计数、无关日志和全部旧事件不进入每轮上下文。后续工具返回观察，模型据此继续决策；宿主在任务结束时保存简短结果。

## 初始模型配置

配置通过环境变量提供；本地 `.env` 是进程环境的配置来源，不提交 Git。示例变量见仓库 `.env.example`，`scripts/run-agent.ps1` 读取 TPA_ 变量到进程环境；已经设置的环境变量优先。Python 只从环境读取凭据。

| 配置 | 起步值 | 用途 |
| --- | --- | --- |
| API 地址 | `https://api.deepseek.com` | 官方接口 |
| 模型 | `deepseek-flash` | 用户指定的 DeepSeek V4.1 Flash；使用官方接口模型名 |
| 思考模式 | `disabled` | 首轮工具动作任务先用快速非思考模式，复杂任务需要时再调整 |
| 单次最大输出 | `1024` tokens | 容纳工具参数和简短说明，避免长篇输出 |
| 单任务最大模型请求 | `8` 次 | 首轮最小闭环的执行预算，后续按任务调整 |

模型名和 thinking 开关依据 [DeepSeek 官方接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)。当前启动器和 Python Agent 已使用这些默认值；环境变量可覆盖。

## 第一轮怎样接

已实现的入口：Python 3.12 标准库，`agent/run.py` 调用 Chat Completions 和模型工具；`game_actions` 按顺序通过原有 TPA/request.json / response-id.json 执行动作，所有游戏动作仍由游戏线程处理。无需第三方 SDK、新服务或游戏重启。

```powershell
.\scripts\run-agent.ps1 -CheckApi
.\scripts\run-agent.ps1
.\scripts\run-agent.ps1 -Goal '向左走一小段，然后停止并报告位置变化。'
```

不传 Goal 时使用 weapon-test.md；可用 `-GoalFile` 换任务模板，`-MaxTurns` 改本轮预算。测试世界必须保持前台，且不要同时运行其他控制脚本或手动发 AI 命令。本机这轮通过进程级 HTTP_PROXY / HTTPS_PROXY=http://127.0.0.1:7890 访问 API；Python 也支持直接使用当前网络环境。

工具参数为 commands（最多 6 条白名单命令）和 wait_seconds（0–15 秒）。命令之间不等待动作结束；移动后立即攻击会替换移动，应分开提交并等待移动完成。每批执行后返回紧凑状态和最近 12 条事件。没有开放任意 shell、其他模组命令或删除角色。模型决定顺序，宿主不写死木剑先测还是铁阔剑先测。

最多请求模型 8 次，API 超时 45 秒，游戏请求超时 5 秒；失败不自动重放有副作用的动作。任务正常结束、预算用尽或出现异常时尝试 stop，保留 AI 和默认自动重生；失焦导致 stop 无法确认时记录 stop_error，原生动作时限仍生效。报告保存到 `.local/test-results/agent-日期时间-标识.json`，包含模型实际工具调用、游戏结果和用量，不包含请求凭据。

默认武器测试额外按实际 item-hit 判定任务是否完成。模型报告成功但缺少某把武器证据时，结果为 task_incomplete，脚本失败退出。自定义 Goal 只记录模型报告及游戏证据，不假装已有通用自动验收器。模型结论和游戏事实需要区分。

只需形成一次“状态 → 模型选择工具 → 游戏执行 → 返回实际结果”的闭环。然后运行上述两种已有武器的简短任务，不遍历全武器，不扩建 RAG、数据库或长期记忆，也不在 API 等待期间阻塞游戏主线程。本地外部 Agent 可以复用正在运行的游戏，无需为这一步重启游戏。

首轮实际结果与发现的问题见 validation.md 的 API Agent 首轮记录。完整保留了该轮模型误判，不把修正后的提示词和结果判定写成已经再次通过在线测试。
